# 持久记录、恢复与复习

## 记录位置

按课程分开保存两份运行记录，不把学生数据写入 Skill 的模板：

```text
<课程工作目录>/.learning/<course-id>/
├── progress.md
└── learning-gaps.md
```

先查找课程现有的学习记录，沿用既有位置和身份，不创建重复记录。新课程默认使用用户提供资料所在的课程工作目录；如果只是上传文件，使用本任务明确的可写项目目录。多门课程身份不清楚或目的位置确实有歧义时，只询问缺失的信息。

`course-id` 使用稳定的课程名或课程编号；Lecture ID 使用材料或用户给出的编号，不能每次因标题略变而新建课程。连续学习不把上一 Lecture 合并进本 Lecture。

新课程在材料和身份明确后，从 [进度模板](../assets/templates/progress.md) 和 [不足模板](../assets/templates/learning-gaps.md) 初始化。模板占位符不是学生数据；创建 Skill 本身时不初始化实际学习记录。

## 两份文件各自负责什么

`progress.md` 保存：课程身份、当前和上一 Lecture、材料读取范围、内容地图与分类、更正历史、章节顺序、能力目标与验证证据、检测档案、复习情况、会话状态、暂停位置及下一步。检测档案包括固定版本的完整题目、评分依据和真实作答。

`learning-gaps.md` 保存：按课程和 Lecture 组织的具体薄弱能力、观察证据、诊断、提示或补教、独立验证、当前状态与历史。能力是否独立通过以 `progress.md` 为准；不足文件记录原因和过程，不单独复制维护通过日期或复习日程。

用稳定能力 ID 连接两份文件，如 `L03-C02-A01`。新增不足使用稳定 Gap ID。同一个能力反复出现同类问题时更新原记录，避免重复创建；新的错误类型可以另建记录。

## 状态约定

能力状态：

- `unverified`：尚无充分独立证据。
- `assisted`：在提示、示范或看过答案后完成，待新题独立验证。
- `independent_pass`：无提示完成适当解释及应用／推导／分析，记录实际题目和证据。
- `needs_recheck`：出现新的错误或其他证据，需要复查或补教。
- `skipped`：用户明确跳过，不能视为已掌握。

章节状态：`not_started`、`learning`、`verified`、`skipped`。只有本章所有要求掌握的能力独立通过才能标为 `verified`。

Lecture 状态：`not_started`、`learning`、`assessment_pending`、`remediation`、`completed`、`completed_with_gaps`。`completed` 要求所有目标能力独立通过且整套检测和必要补教复测完成。只有用户明确选择结束这个 Lecture、将剩余内容留待以后，而仍有未学、未验证、跳过项或不足时，才使用 `completed_with_gaps`，分别说明具体内容；未验证不自动等于已确认不足。

会话状态单独记录为 `active` 或 `paused`。“今天先到这里”“下次继续”、疲劳暂停或会话中断只将会话标为 `paused`，保留 Lecture 原阶段和当前 Lecture 身份。含糊的结束表达默认按暂停处理，不把 Lecture 移入已完成。恢复时将会话设为 `active`，从原阶段、原位置继续；明确返回已结束但有缺口的 Lecture 时，根据剩余任务恢复为 `learning`、`assessment_pending` 或 `remediation`，保留历史。

不足状态：`pending_verification`、`confirmed`、`recheck_pending`、`resolved`。仅反复询问时先用 `pending_verification`；明确错题或验证失败可以用 `confirmed`。补教后等待独立验证用 `recheck_pending`，取得证据后用 `resolved`。后续再次失误可重新打开，保留历史。

复习状态与能力状态分开：`offered`、`skipped`、`in_progress`、`done`。跳过复习或检测中断不抹掉之前真实的独立通过证据。

## 主动感知不足

有价值的信号包括：同一逻辑环节反复卡住、把两个概念混淆、无法解释关键条件、依赖提示、方法选择错误、漏掉推导依据或在不同题中重复同类错误。

这些都需要保留实际证据，不能仅凭学生提问多、表达慢、自信程度或答案措辞推断能力差。

1. 记录材料位置和触发信号。
2. 用短解释检查、新例子或局部任务判断是否存在不足。
3. 区分深入追问、题目歧义、AI 讲解／答案错误与学生概念错误。
4. 有证据时记录具体错误原因，表述为可验证的行为，避免人格或泛化判断。
5. 补教后以新题无提示表现验证，并更新原记录。

## 检测档案与跨会话恢复

在 `progress.md` 的对应 Lecture 下，按检测 ID 和版本保存一份完整档案。Lecture 综合检测必须发题前保存；章节检测或补教复测若需要暂停续做，也按此保存。

- 检测 ID、版本、类型、创建时间、独立检测／辅助练习模式和提交状态。
- 固定题号、完整题干、全部条件、必要图表内容或可再次读取的稳定附件位置；网页链接或知识点摘要不能替代完整题目。
- 每题对应能力、来源／改编关系，以及发题前核验的解答、有效替代解法和评分依据。
- 按题号保存学生实际答案、答案修订顺序、提示内容及是否整套提交；没有作答的题保持未作答。
- 当前暂停位置、下一步，以及试卷修订说明。

题目及内部评分依据与学生作答分段保存。内部解答供恢复和统一反馈使用，不能自动展示在检测对话、待答试卷或进度摘要中；学生明确要求看解答时，按转为辅助练习的规则处理。

恢复时先读固定档案与已有答案，继续同一版本。不得因为换了会话就重出题、覆盖旧答案或静默修改判分依据。确需修正错误题目或解答时，保留旧版本，创建明确的新版本并记录影响，撤销由出题错误产生的不足结论。

若原档案不完整且无法恢复，说明缺失内容，不假称原样续接；经用户明确选择，可以补齐原题或开始新的检测版本，保留原检测为未完成。

## 保存时机与完整性

- 规划和用户更正之后，记录内容地图及更新后的顺序。
- 有效作答、确认不足、补教、验证、跳过和暂停之后及时保存，不仅在会话末尾保存。
- 在结束会话、疲劳暂停或准备切换 Lecture 时保存下一步和未完成检测档案；区分会话暂停与明确结束该 Lecture，按上面的状态规则处理。
- 修改前先读当前文件，保留用户文字和历史，不用模板覆盖已存在记录。
- 同一次更新两份文件后核对能力 ID、状态和证据；若写入部分失败，下次开始先修复不一致，不静默丢失数据。
- 日常教学只保存恢复和诊断所需的简短证据，不默认复制整段聊天记录。检测档案必须保留完整试题、核验后的评分依据和实际作答，不能压缩为无法恢复的摘要或临时聊天位置。
- 记录来自课程的重点判断、AI 推断和用户要求的不同来源。真实日期使用用户可用时区。

无持久化能力时，提供本次变更内容供用户保存，说明未写入文件；后续恢复需要实际记录，不能假装仍记得上一会话。

## 下次学习开始

先读两份记录，再确定是同一 Lecture 续学还是新 Lecture。

- 续学：说明已完成内容、当前薄弱点和暂停位置，继续该 Lecture。不重复询问是否复习“上一讲”。
- 新 Lecture：上一 Lecture 有已学内容时，询问是否复习；上一 Lecture 部分未学则准确标明，不假称学完。
- 用户同意：以那个 Lecture 为单位，覆盖知识结构及代表性能力，重点复查未解决和待复查的不足，同时检查一些曾独立通过的内容。
- 用户跳过：记录选择，继续当前 Lecture；先前已掌握状态保持。只有新课确实依赖某项不足时，解释依赖并补必要前置知识，不变相强迫整讲复习。
- 用户点名复习其他 Lecture 时遵从选择，并保持 Lecture 边界。

复习先要求从记忆解释或处理新输入，再按表现补讲。不要直接重读整份 PPT 后把“听过”算作复习通过。更正和复测依旧用新题，更新真实证据。

不自动创建提醒、定时任务或日历安排；下一次会话的复习选择由本 Skill 的入口流程处理。
